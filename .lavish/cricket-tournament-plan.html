Product plan · decision round 1

A simpler way to run a cricket tournament

Create a tournament, keep fixtures and results in sync, and let anyone follow the score from the boundary or at home.

Responsive web appFirebase HostingFirestore data
Goal and starting point

Make tournament day easier to run

Organizers need one place for teams, fixtures, and results. Players and spectators need a score they can trust and check on a phone.

Starting point: this repository has no app implementation or existing product design system. The audience, scoring depth, and launch scope are still open.

Recommended first release
  1. 01 Create tournament, teams, and squad lists.
  2. 02 Choose a format and publish fixtures.
  3. 03 Record a match and publish a live scoreboard.
  4. 04 Show standings and completed results.

Keep the first release focused on organizers and public viewing; add extra account types only if they solve a clear launch need.

Decision 05 · Firebase constraint

Do you need uploaded photos or files?

Spark supports free quotas for Firestore and Hosting, but Cloud Storage for Firebase requires Blaze as of February 3, 2026. Firestore can store tournament records; it is not a file bucket.

Proposed build sequence
  • 1. Tournament setup - teams, squads, format, overs, and match rules.
  • 2. Fixtures and standings - generate matches and update points from results.
  • 3. Match scoring - scorer workflow, match state, and public live score.
  • 4. Release basics - sign-in, role checks, Firestore rules, and Firebase Hosting.
Constraints and risks
  • Free quotas can be exceeded; monitor reads, writes, storage, and Hosting traffic.
  • On Spark, Cloud Storage for Firebase is unavailable. Do not design uploads into the free-only path.
  • Ball-by-ball scoring needs clear correction and match-finalization behavior before implementation.
  • Competition rules vary; overs, tie-breaks, points, and abandoned matches need explicit defaults.
